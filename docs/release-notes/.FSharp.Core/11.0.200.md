### Added

### Fixed

* Fix `let` bindings reaching LINQ providers as `Expression.Block`, which no provider translates: in lambdas handed to a provider, records and anonymous records with fields written out of order, tupled lambda parameters, struct copies such as `x.Nullable.HasValue` and explicit `let`s now produce plain expressions. ([Issue #11131](https://github.com/dotnet/fsharp/issues/11131), [Issue #15648](https://github.com/dotnet/fsharp/issues/15648), [Issue #11332](https://github.com/dotnet/fsharp/issues/11332))
* Fix a lambda nested in another lambda that goes to a LINQ provider, such as `db.Orders.Any(fun o -> o.CustomerId = c.Id)` inside a query `where`: it becomes a quoted lambda, as in C#, instead of a run-time call to `QuotationToLambdaExpression` that no provider can translate. ([Issue #2758](https://github.com/dotnet/fsharp/issues/2758))
* Fix struct tuples in query expressions and in lambdas converted to LINQ expression trees: selecting one no longer fails with "unreachable", and taking one apart no longer fails with a tuple index out of range. ([Issue #15522](https://github.com/dotnet/fsharp/issues/15522))
* Fix LINQ providers failing on queries composed over a tuple or record projection (for example a `Where` on the result of `select (c.Id, c.Name)`, or a record read by the next `for`): tuple, struct tuple, record and anonymous record constructions now name the member each argument becomes, as C# anonymous types do. ([Issue #3782](https://github.com/dotnet/fsharp/issues/3782), [Issue #15133](https://github.com/dotnet/fsharp/issues/15133))

### Changed

* A query that ends by selecting a tuple or record now gives the LINQ provider a single `Select` building it, as C# does, instead of a `Select` of an internal `AnonymousObject` followed by a second `Select` converting it.
